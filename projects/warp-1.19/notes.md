- Top-level licence: Apache-2.0, tier 1. Recorded with `moatlib.py set-license-spdx`; evidence: https://github.com/NVIDIA/warp/blob/release-1.19/LICENSE.md.
- File-level scan: `python3 utils/licenses.py scan-nvidia agent_space/warp-1.19-screen` found `README.md`, `licenses/cuda-LICENSE.txt`, and `licenses/libmathdx-LICENSE.txt`. The README says the source build automatically retrieves libmathdx, that prebuilt packages statically include it, and that it is governed by NVIDIA's Software License Agreement (`README.md:301-307`). These are real distribution/licensing concerns, not false positives from NVIDIA copyright headers. A person must obtain a legal ruling on whether the 1.19 release may be built/distributed without MathDx and whether the CUDA EULA text may remain in the release before this line is shipped.
- Existing AMD work: `https://github.com/AMD-Ecosystem/warp` is a fork of `NVIDIA/warp`, with active `amd-integration` and related branches, an ROCm build/test setup, and a published 1.13.0 release line. Its HIP work includes `hip_util.h`, HIPRTC, HIP graph support, rocWMMA, and ROCm CI. This is authoritative AMD-owned work and is the baseline to build on, not a community hint. NVIDIA upstream PR #1932 (https://github.com/NVIDIA/warp/pull/1932) added WIP HIP shims and was closed unmerged; upstream PR #1770 was also closed WIP scaffolding. NVIDIA/warp has no open PR returned by `gh pr list --state open --search 'hip OR rocm OR amd'`.
- AMD's current release/update work is not yet at 1.19: `AMD-Ecosystem/warp` has `release/1.13.0.amd0`, and open PR #21 is explicitly an update of the gfx1151 port to Warp v1.18.0. Its `amd-integration` branch is substantially behind/diverged from NVIDIA `release-1.19` (GitHub compare: 57 ahead / 781 behind, merge base `d8f5e52d02990e21e2df4b67298423d7b98598fb`). Coordinate with that team before deciding whether the 1.19 line should be based on their current release work or independently synchronized.
- Intake recommendation: continue only as validation/improvement of the authoritative AMD port, not a clean-room HIP port. Viability is technically plausible, but overall intake is **blocked on a human legal decision** about the proprietary license material and **coordination** with the AMD Warp maintainers about the in-flight 1.18 -> 1.19 update. Do not enter planning or source work until resolved.
